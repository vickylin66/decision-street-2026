# 《決策之道，老街有燈》The Way of Decision (Decision Street 2026)

**讀一篇，撕一張日曆，點亮一間街屋。**

把電通《2026 決策智慧：Agentic 時代，重塑品牌與人的真實距離》22 篇觀點，做成一條可以逛、可以點亮的台灣騎樓老街。

- **線上體驗網址**：<https://vickylin66.github.io/decision-street-2026/>
- **作品性質**：電通內部 Vibe Coding 比賽參賽作品
- **核心架構**：純靜態單頁應用（SPA）· 本地受控 WebGL 3D 引擎 · Zero-PII 零個資架構

---

## 一、 為什麼做成一條老街（策展與心理洞察）

面對全書 22 篇、約 200 頁的高密度決策策略刊物，傳統 PDF 與長條捲軸容易引發讀者的「資訊超載」與「閱讀倦怠」。本專案旨在以在地人文空間敘事與行為設計學解決三件事：

1. **讓讀者找到專屬入口（低摩擦探索）**：
   回答三個情境導引問題（職務、產業、最想解決的事），系統自動排出 6 篇由入門到深入的客製化閱讀動線，消除「不知從何讀起」的心理門檻。

2. **讓長篇閱讀具備即時微回饋（蔡格尼效應與峰終定律）**：
   - **蔡格尼效應（Zeigarnik Effect）**：介面即時標記點燈進度（如 `0 / 22 間亮燈`），利用未完成的留白喚醒讀者補完的心態。
   - **即時微回饋**：每讀完一篇，伴隨清脆的撕日曆翻頁感，日曆化為一盞明燈飛向街區，點亮一間街屋與騎樓紅燈籠。
   - **峰終定律（Peak-End Rule）**：22 間全亮時，老街進入黃昏，觸發平溪天燈粒子升空盛典，天空以點雲凝聚排出一句全書結語，將獲取資訊昇華為文化祈福儀式。

3. **讓全書擁有立體思維地圖（空間化動線）**：
   老街由左至右結構化為「序章、People、Model、AI」四大街區，對應刊物的四個核心單元，讀者隨時掌握全局座標與未竟之處。

> **建築歷史與單元演進對齊**：  
> 四個街區的建築依序為**牌樓式街口、閩南紅磚街屋、巴洛克洋樓、木質現代街屋**，精準對應台灣市井建築年代的遞嬗，亦呼應思維從傳統邁向 AI Agentic 時代的序階。

## 二、 閱讀流程與雙層內容深度

| 閱讀階段 | 核心機制 | 老街上的視覺與狀態反饋 |
|---|---|---|
| **開始** | 回答 3 道情境題，或讓 AI 導覽員自動帶逛老街一圈 | 導覽時老街動態漫遊，預覽全街全亮之黃昏盛況 |
| **第一階段** | 6 篇個人專屬路線（第一篇固定為全書入門導讀） | 每讀完一篇點亮一間街屋，窗櫺溢出金光、騎樓泛起暖燈 |
| **第二階段** | 讀完路線後選擇「往深處走」或「往旁邊走」，系統動態再排 5 篇 | 街口掛起寫著讀者職務的直式招牌；讀完後讀最多的街區拉起慶典燈籠串 |
| **自由閱讀** | 解鎖自由探索模式，全部 22 篇任意選讀 | **22 間全亮終局**：老街切換為黃昏夜色、放天燈，天空以點雲排成字句 |

### 雙層閱讀深度設計（兼顧策展提煉與原刊原貌）

每篇文章標題下方配置切換按鈕，提供兩種深度閱讀選擇，並落實清晰的視覺層次（Visual Hierarchy）：

- **精華導讀（主要按鈕 Primary Action）**：提煉 1 句核心頓悟與 3 個落地重點，約 3 分鐘速讀，讀完即可觸發撕日曆微獎勵。
- **看原刊全文（次要按鈕 Secondary Action）**：以原刊頁面高清圖逐頁翻閱，支援放大檢視，篇末附帶各事業體商務聯絡窗口。

## 三、 技術架構（受控原生與極致輕量化）

本專案拒絕盲目引入龐大黑箱框架，堅持採用受控的純原生前端與本地託管 3D 渲染：

| 項目 | 實作方案與工程細節 |
|---|---|
| **網頁載體** | 單一 `index.html`，純原生 HTML5、CSS3 與現代 Vanilla JavaScript，無前端框架編譯負擔。 |
| **3D 老街引擎** | **本地受控 WebGL**：引入 `three.js r128`（MIT 授權，由本 Repo 自行託管，徹底消除外部 CDN 斷鏈與供應鏈污染風險）。 |
| **程序化生成** | **零外部 3D 模型依賴**：街屋建築立面、磚牆紋理、背景街景皆由程式即時程序化繪製（Procedural Generation），**不加載任何外部 `.gltf` / `.glb` 巨型模型檔**，全站首屏極度輕巧。 |
| **建築家號牌** | 每間街屋在山頭中央以雕花家號牌標示篇號（考據大稻埕泥塑花框語彙，簡化為花瓣邊與捲草；篇號採金色，避開中式傳統忌諱；雕花在低解析度下仍清晰）。尚未點亮的地基以同色系浮動標籤標示；四條道路標有街區名牌；後方街區隨閱讀進度逐步浮現。 |
| **撕日曆動畫** | 採用瀏覽器原生 **Web Animations API** 進行流暢影格變換。 |
| **天燈與點雲** | 將全書結語取樣為點陣座標，透過 WebGL 粒子系統運算，光點自老街升空並於夜空聚合為字型。 |
| **原刊隨選載入** | 186 張高品質 WebP 圖片（22 篇 184 頁 ＋ 聯絡窗口），採「讀到該頁才加載（On-demand）」並「預載下一頁（Preload）」機制。 |
| **閱讀狀態管理** | 透過原生 `localStorage` 鎖定本機，無伺服器資料庫依賴。 |
| **無障礙 (A11y)** | 遵循 W3C ARIA 語意規範（`role="tablist"`、`role="dialog"`、`aria-live="polite"`）；支援作業系統「減少動態效果（Prefers-Reduced-Motion）」設定。 |
| **平穩功能降級** | 當瀏覽器 WebGL 載入失敗或硬體算力受限時，老街自動平穩降級為純文字引導，問卷、精華導讀、原刊翻閱與撕日曆核心功能照常運作。 |

## 五、 部署思路與極致流量精算

- **部署模式**：純靜態網站（Serverless Static），直接託管於 GitHub Pages，透過全球邊緣 CDN 加速分發。
- **首屏秒開體驗**：首頁主 HTML 與本地 3D 函式庫，合計僅約 **0.75 MB**，一般行動網路秒開。
- **原刊翻閱效能**：原刊頁面經 WebP 高效壓縮，每頁平均僅約 **133 KB**；在微弱的 1.5 Mbps 手機訊號下約 0.7 秒即完成載入，並在背景自動預載下一頁。
- **評審實體情境 vs. 壓力上限精算**：
  - **實際評審負載（11/23 至 11/30）**：本賽事由 **三位以上專業評審** 組成閉門審查。於一週評估期內，即使每位評審反覆全量審閱 22 篇所有頁面（186 頁），實質出網流量亦**低於 300 MB**，對系統而言幾近零負載。
  - **高標抗壓推估（保留之理論上限）**：即使未來擴大推廣，以每月 2,000 人次、每人深度翻閱 3 篇原刊估算，全月出網流量僅約 **8 GB**，僅佔 GitHub Pages 每月免費流量上限（100 GB）的 **8%**。
  - **結論**：實體評審需求**遠低於** GitHub Pages 頻寬限制（消耗不及 0.3%），專案具備極高的抗壓安全邊際（Safety Margin）；全站資產總容量約 **27 MB**，亦僅佔倉庫容量上限（1 GB）的 **2.7%**。
- **快取備註**：GitHub Pages 具備約 10 分鐘邊緣快取，測試新版本時可於網址後附加 `?v=版本號` 強制刷新。

## 六、 企業級資安與法務合規自評 (Security & Governance)

本專案自架構層級嚴格遵循企業級資安、隱私個資與智財法務規範：

| 檢核項目 | 合規落實方案 |
|---|---|
| **架構最小攻擊面** | 純靜態零後端架構（Serverless SPA），無後端主機、無資料庫、無暴露之 API Key 與管理員帳密，自物理層隔絕滲透攻擊。 |
| **落實 Zero-PII 隱私原則** | 嚴格符合台灣《個人資料保護法》及國際 GDPR 最小化原則。閱讀進度、問卷選項 100% 留存在讀者端瀏覽器（`localStorage`），不採集、不上傳任何使用者識別資訊。 |
| **原始碼防護** | 全站代碼不含內部 Token、金鑰或客戶機密；每次版本 Commit 前均經過自動化敏感詞與憑證掃描。 |
| **供應鏈斷鏈防護** | 3D 渲染庫由本地倉庫自託管提供；對外連線僅保留 Google Fonts，當字型無法載入時系統自動回退至原生系統字體。 |
| **刊物授權與商標避險** | 刊物內容依主辦單位規定公開展演；全站立面皆為代碼即時程序化繪製，未重製任何受版權保護之特定地標，**主動評估並剃除台北 101 商標侵權風險**。 |
| **商業聯絡資訊防護** | 聯絡窗口為刊物本身公開之商務窗口；前端原始碼不以明文 Email 儲存，而於讀者點擊瀏覽時動態組合，杜絕爬蟲惡意蒐集。 |
| **內容精準度審查** | 篇名、作者、職稱、頁碼皆對照全本原刊 PDF 首頁逐一核對，共嚴謹比對並裁決 **25 項篇名職稱差異**。 |
| **開源授權遵循** | `three.js` 遵循 MIT 授權條款並保留授權宣告；Google Fonts 遵循 SIL Open Font License 開源授權。 |

## 七、 製作歷程（Vibe Coding 人機協同）

本專案為標準 **Vibe Coding（自然語言引導與 AI Agent 深度協同）** 實踐範例。由策展者主導商業價值判斷、動線設計、建築美學與資安邊界，AI（Anthropic Claude）負責生成代碼草案、演算法實作與即時自我修正（Self-Correction）：

1. **內容精準核對**：比對全刊 PDF 與線上資料，整理出 25 項篇名、作者與職稱差異，由策展者逐一裁決確保權威性。
2. **閱讀優先的版面決策**：在「老街為視覺主體」與「內容為閱讀主體」兩種版面原型中，裁決採用「閱讀為主、老街為回饋」，撕日曆時老街才動態展開，形式不喧賓奪主。
3. **四街區建築風貌迭代**：以自然語言引導先繪製平面立面示意圖，確認時代風格後再轉化為 3D 代碼；依反饋調整：序章去除沉重黑調、People 增設紅布店招、Model 融入巴洛克泥塑花草、AI 重構為木質現代簡約風。
4. **全文呈現方式重構**：初版嘗試從 PDF 抽取文字（完成 49 條人工校對），後評估刊物含大量精美圖表，果斷改採 WebP 原刊逐頁翻閱，兼顧專業排版美感與傳播正確性。
5. **架構降級與流量防護**：考量企業內網資安，將 3D 庫自外部 CDN 收回本地託管；加入 WebGL 失敗時的文字降級機制，並以實測檔案大小完成流量極限精算。
6. **動態推薦演算法驗證**：撰寫腳本自動模擬 **240 種讀者問卷組合**，排查出「原規則會導致 85% 讀者被推薦過多序章」的邏輯死角並完成權重修復。
7. **自然語言引導代碼重構（Self-Correction）**：在重構建築山頭立面時，以自然語言提示 AI 自動檢測重複邏輯，AI 自行識別並回報*「舊的後排屋頂程式已包含在第一段替換範圍，第二段移除是多餘的。拿掉那一步重來」*，展現標準的人機協同除錯節奏。
8. **細節打磨與沉浸感**：實作撕日曆化為光點飛向老街、天燈點雲排列結語、AI 導覽員、雕花家號牌、街區路牌，以及隨閱讀進度逐步浮現的「越讀越熱鬧」動態街區。

## 八、 在本機執行 (Run Locally)

本專案採零依賴純靜態結構，無需配置 Node.js 或複雜構建環境：

```bash
# 1. 複製專案庫
git clone https://github.com/vickylin66/decision-street-2026.git

# 2. 進入專案資料夾
cd decision-street-2026

# 3. 使用 Python 原生伺服器開啟（或任意靜態伺服器）
python3 -m http.server 8000

# 4. 以瀏覽器開啟 http://localhost:8000
```
